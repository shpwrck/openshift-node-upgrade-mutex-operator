## Development

The operator is an [operator-sdk](https://sdk.operatorframework.io/) Ansible operator. `watches.yaml` maps each custom
resource to a role in `roles/`, and the image is `quay.io/operator-framework/ansible-operator:v1.42.3` plus the
collections in `requirements.yml` (`kubernetes.core`, `operator_sdk.util`).

| Path | What it is |
| --- | --- |
| `roles/` | One role per CR (`mutexrule`, `mutextarget`, `mutexrunconfig`); each has a README. |
| `watches.yaml` | CR to role mapping, reconcile period and the MutexRunConfig finalizer. |
| `config/` | Kustomize manifests: CRDs, RBAC, manager Deployment, CSV base (`config/manifests`), samples, scorecard. |
| `catalog-template.yaml` | Source of truth for the file-based catalog (an `opm` basic template). |
| `catalog/` | The rendered catalog, committed so it can be validated and built without pulling images. |
| `bundles/<VERSION>/` | Generated by `make bundle`; git-ignored. |
| `hack/` | Helper scripts used by the Makefile and CI. |
| `molecule/` | Test scenarios. |
| `docs/` | `USAGE.md` and `DEVELOPMENT.md`, the sources of `README.md`. |
| `sample-manifests/` | Example MachineConfig, NFD instance, Job and CatalogSource. |

### Prerequisites

* `make`, `curl`, `sed` and `awk`, GNU or BSD.
* **podman**, the default `CONTAINER_TOOL`. To use docker, pass `CONTAINER_TOOL=docker`.
* For `make lint`: Python with `yamllint`, `ansible-core` 2.18 and `ansible-lint`. CI pins `yamllint==1.38.0`,
  `ansible-core==2.18.18` and `ansible-lint==26.9.0`. `shellcheck` checks `hack/*.sh`.
* `kubectl` or `oc` for `install`, `deploy` and `run`.
* Credentials for the registry in `IMAGE_TAG_BASE`, only to push images. Building needs no registry login: the base
  images are public, and nothing comes from `registry.redhat.io`.

The Makefile downloads its other tools into `./bin` at pinned versions: operator-sdk v1.42.3, kustomize v5.8.3 and yq
v4.54.1. The ansible-operator and opm versions are read from the `FROM` lines of `Dockerfile` and `catalog.Dockerfile`.
To use your own binary, pass its path, for example `make bundle OPM=/usr/local/bin/opm`.

### Version and registry

`.envrc` holds the release settings: `MAJOR`, `MINOR`, `PATCH`, `IMAGE_TAG_BASE`, and `USE_IMAGE_DIGESTS=true`, which
pins the operator image by digest in the bundle. [direnv](https://direnv.net) exports them. Without direnv the
Makefile still reads the version from `.envrc`, but `IMAGE_TAG_BASE` falls back to the placeholder
`example.com/openshift-node-upgrade-mutex-operator`, which `make release` refuses. Set `IMAGE_TAG_BASE` to a registry
you can push to before you push anything.

### Make targets

`make` on its own prints this list (`make help`).

| Target | What it does |
| --- | --- |
| `document` | Regenerates `README.md` (`docs/USAGE.md`, then `docs/DEVELOPMENT.md`) and the CSV `spec.description` (from `docs/USAGE.md`). |
| `lint` | `yamllint` (with `hack/yamllint.yaml`), `ansible-lint roles/`, and `ansible-lint` on `molecule/` with `molecule/.ansible-lint`. |
| `run` | Runs ansible-operator locally against the cluster in your kubeconfig. |
| `docker-build` / `docker-push` | Builds or pushes the operator image `IMG` (default `$(IMAGE_TAG_BASE):$(VERSION)`). |
| `docker-buildx` | Builds and pushes a multi-arch image for `PLATFORMS`. |
| `image-smoke-test` | Checks a built image without a cluster: collections, Python libraries, and a syntax check of every role. |
| `install` / `uninstall` | Applies or deletes the CRDs. |
| `deploy` / `undeploy` | Applies or deletes `config/default` with `IMG`. |
| `bundle` | Generates and validates `bundles/<VERSION>/` (manifests, metadata, scorecard tests, `bundle.Dockerfile`). |
| `bundle-validate` | `operator-sdk bundle validate` with the optional `operatorframework` suite. |
| `verify-manifests` | Checks the default and manifests overlays, and the bundle CSV, for known regressions. |
| `bundle-build` / `bundle-push` | Builds or pushes the bundle image `BUNDLE_IMG`. |
| `catalog-add` | Adds `BUNDLE_REF` to `catalog-template.yaml` as the new head of the `alpha` channel. |
| `catalog-render` | Renders the template into `catalog/` (pulls every bundle image) and validates it. |
| `catalog-validate` | Validates `catalog/` and checks that it matches the template, without pulling images. |
| `catalog-build` / `catalog-push` | Builds or pushes the catalog image `CATALOG_IMG`. |
| `release-check`, `release`, `latest`, `increment` | The release flow below. |

`make bundle` and `make deploy` run `kustomize edit set image` in `config/manager`, which changes
`config/manager/kustomization.yaml`. Do not commit that change unless you mean to.

### Documentation

Edit `docs/USAGE.md` and `docs/DEVELOPMENT.md`, never `README.md`. Then run `make document` and commit the result.
`docs/USAGE.md` is also the operator's description on OperatorHub. Use absolute links in it, because relative links do
not resolve there. Keep its permissions table in step with `config/rbac/role.yaml`.

### Running and testing

* **Lint:** `make lint`. `ansible-lint` installs `requirements.yml` into `./.ansible/collections` (git-ignored), so
  the first run needs network access. Both runs use the repository root as the project directory; that is why the
  molecule run passes `--project-dir .`. With `--offline` nothing is installed, and the collections must already be
  in your collections path.
* **Against a cluster:** `make install` to apply the CRDs, then either `make run` (local) or
  `make docker-build docker-push deploy IMG=<image>`. `make run` does not set `POD_NAMESPACE`, so every namespace is
  allowed. Export `POD_NAMESPACE=<namespace>` first to test the namespace boundary. Only an OpenShift cluster has the
  MachineConfigPool and ClusterVersion APIs the operator needs. Molecule's `default` scenario then refuses this
  cluster: its prepare, converge and destroy stop when an operator CRD lacks the label its converge sets, or when a
  MutexRule, MutexTarget or MutexRunConfig exists outside its test namespaces (`molecule/default/tasks/olm_guard.yml`).
  Run it on a fresh cluster instead, or run `make undeploy` (after `make deploy`) or `make uninstall` first. Both
  delete the CRDs, and with them every MutexRule, MutexTarget and MutexRunConfig in the cluster. Delete the
  MutexRunConfigs first, while the operator still runs: their finalizer restores the pools and nodes, and without the
  operator it never completes, so the CRD deletion waits.
* **Molecule:** `molecule test -s kind` runs the kind scenario in `molecule/kind`. It creates a throwaway kind cluster,
  deploys the operator and checks the reconciles that work without OpenShift. It works with docker, or with podman
  (`KIND_EXPERIMENTAL_PROVIDER=podman`). Rootless podman needs cgroup v2 with the `cpu` controller delegated to the user
  (systemd `Delegate=yes`), see the [kind rootless guide](https://kind.sigs.k8s.io/docs/user/rootless/). The scenario's
  own files list what it covers.
* **Scorecard:** `operator-sdk scorecard bundles/<VERSION>` runs the `basic` and `olm` suites against a cluster.

### Continuous integration

`.github/workflows/ci.yaml` runs on every pull request and on pushes to `main`. It has read-only permissions, uses no
secrets and pushes nothing.

* **Lint:** `make lint` (yamllint, ansible-lint) and `shellcheck hack/*.sh`.
* **Build and validate**, with podman and `IMAGE_TAG_BASE=localhost/...`: `docker-build`, `image-smoke-test`,
  `bundle` with `bundle-validate`, `verify-manifests`, `bundle-build`, `catalog-validate` and `catalog-build`.

### Releasing

The catalog source of truth is `catalog-template.yaml`, an opm basic template that lists every released bundle and the
upgrade edges of the `alpha` channel. `catalog/openshift-node-upgrade-mutex-operator/catalog.yaml` is rendered from it.

1. Set `IMAGE_TAG_BASE` (in `.envrc`) and log in to that registry. Check the version in `.envrc`. It must not be in
   `catalog-template.yaml` yet.
2. Run `make release`. It runs `release-check`, then:
   * builds and pushes the operator image;
   * generates the bundle, which pins the operator image by digest when `USE_IMAGE_DIGESTS=true`, then builds and
     pushes the bundle image;
   * `catalog-add` makes the bundle the new channel head, with `replaces` set to the old head and `skipRange: <VERSION`;
   * `catalog-render` pulls every bundle image and takes a few minutes;
   * builds and pushes the catalog image, and tags all three images as `:latest`.
3. Commit `catalog-template.yaml` and `catalog/`.
4. Run `make increment` to bump `PATCH` in `.envrc`, then commit it.

`make release` records the bundle in the catalog by tag (`BUNDLE_IMG`) and refuses any other `BUNDLE_REF`. The
bundle's digest is only known once it is pushed, because every `make bundle` writes a new `createdAt`. To record the
bundle by digest instead, run the steps of `make release` one at a time and read the digest of the pushed bundle in
between, for example with skopeo, which uses the podman or docker login:

```sh
make release-check
make docker-build docker-push
make bundle
make bundle-build bundle-push
digest=$(skopeo inspect --format '{{.Digest}}' docker://<IMAGE_TAG_BASE>-bundle:v<VERSION>)
make catalog-add BUNDLE_REF=<IMAGE_TAG_BASE>-bundle@$digest
make catalog-render
make catalog-build catalog-push
make latest
```

`skopeo` prints the full digest, `sha256:...`, so `BUNDLE_REF` gets no second `sha256:` prefix. `catalog-add` does
not check the format of the reference, and running it again for the same version is refused. To undo a wrong
`catalog-add`, run `git checkout catalog-template.yaml` (and `git checkout catalog/` if `catalog-render` already ran),
then run it again.

Then continue with steps 3 and 4.

To publish in the community catalogs, copy `bundles/<VERSION>/` (`manifests/`, `metadata/` and `tests/`) into
`operators/openshift-node-upgrade-mutex-operator/<VERSION>/` of a fork of
[k8s-operatorhub/community-operators](https://github.com/k8s-operatorhub/community-operators) or
[redhat-openshift-ecosystem/community-operators-prod](https://github.com/redhat-openshift-ecosystem/community-operators-prod),
and open a pull request.

### Changing permissions

`config/rbac/role.yaml` is least privilege. Every rule there maps to a call in `roles/` or in ansible-operator itself.
When a role starts using a new resource or verb, add it there, add it to the permissions table in `docs/USAGE.md`, and
run `make document`.

See `docs/HANDOFF.md` for what has to change when the repository moves to a new owner.
